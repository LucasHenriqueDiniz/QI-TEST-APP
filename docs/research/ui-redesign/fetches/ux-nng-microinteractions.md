# Microinteractions in User Experience (NN/g, Alita Kendrick, 2018-10-21)

> Fetched 2026-10-19 · NN/g's definition and purposes of microinteractions; read to frame answer-selection feedback and the "undo/change answer" affordance on the Test question screen.

## What it says

> "Definition: Microinteractions are trigger-feedback pairs in which (1) the trigger can be a user action or an alteration in the system's state; (2) the feedback is a narrowly targeted response to the trigger and is communicated through small, highly contextual (usually visual) changes in the user interface."

> "When a microinteraction is triggered by a GUI command, a visual feedback element will be usually placed in close proximity to that trigger."

> "Button — It depends — If there is no feedback when a user clicks the button, there is no microinteraction"

> "Microinteractions can improve a product's user experience by: Encouraging engagement / Displaying system status / Providing error prevention / Communicating brand"

On the Asana unicorn: "In this case, there are two microinteractions: the utilitarian dialog box and the gamification-inspired unicorn animation." and "In Trello, moving a task to the Done column generates no extra fanfare. And, for many people, that perfectly meets expectations."

On undo:

> "Systems should make it easy to undo actions so that users don't have to jump through hoops to reverse something that they didn't mean to do in the first place. Microinteractions communicate the state of a UI component and suggest that further interaction is possible."

On the Gap heart animation being appropriate:

> "It's subtle enough to not brutally yank the user's attention away from the primary task. (In contrast, an aggressive animation would be too intrusive.)"

> "By only animating the heart for a short duration, this effect remains a microinteraction, as opposed to being inappropriately permanent."

> "[...] directing the user's attention to the effect of a potential accidental activation (something that's sadly all too common in touch-driven user interfaces)."

On tone:

> "Microinteractions shouldn't be fluffy and should always serve a purpose — but that doesn't mean that they shouldn't embody a brand. If your branding is fun and colorful, it's okay to let that show in your microinteractions."

## What it does not say

- No measured effect of microinteractions on engagement or completion; the support is heuristic and case examples.
- Nothing on whether to auto-advance after selecting an answer vs. requiring a "Next/Confirm" tap — the undo passage argues for keeping a moment where an accidental tap can be corrected, but the article does not address the auto-advance question directly.
